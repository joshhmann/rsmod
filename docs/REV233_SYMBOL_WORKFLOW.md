# Rev 233 Symbol Workflow

This is the canonical workflow for RSMod symbol and ID work. It exists because content agents kept
making local aliases or fallback IDs that compiled briefly, then broke `packCache`, boot, or later
content.

## Core Rule

Content adapts to rev 233 symbols. Symbols are not renamed to make content fit.

Use these authorities in order:

1. `rsmod/.data/symbols/*.sym` generated from rev 233 OpenRS2 `runescape/2293`.
2. MCP `osrs-cache` lookups for ambiguous object/NPC/loc candidates.
3. OSRS Wiki for behavior, XP, drops, dialogue, and mechanics.
4. Donor repos only for behavior patterns, never direct IDs.

## Banned Moves

- Do not edit base `.data/symbols/*.sym`.
- Do not add `.local/*.sym` aliases for cache-backed IDs just to use wiki-style names.
- Do not map functional refs to `blankobject`, `nothing_`, or any shared dummy object.
- Do not use `find("name", fallbackId)` for cache-backed IDs.
- Do not promote generated scraper output into runtime code without symbol validation and
  `packCache`.
- Do not trust wiki IDs in Kotlin until mapped to rev 233 `.sym` names.

## Required Symbol Manifest

Before writing code, paste a manifest into the task note or implementation note:

```text
Feature: <feature/task>

objs:
- wiki: <wiki item name> | sym: <obj.sym name> | id: <id> | source: .data/symbols/obj.sym:<line>

npcs:
- wiki: <wiki npc name> | sym: <npc.sym name> | id: <id> | source: .data/symbols/npc.sym:<line>

locs:
- wiki: <wiki loc name> | sym: <loc.sym name> | id: <id> | source: .data/symbols/loc.sym:<line>

seqs/spots/projanims:
- wiki: <behavior/effect> | sym: <type.sym name> | id: <id> | source: .data/symbols/<type>.sym:<line>
```

If a row cannot be filled in, stop and document why before editing runtime code.

## Lookup Procedure

Run local symbol searches first:

```powershell
rg -n "partial_name" .data\symbols\obj.sym .data\symbols\.local\obj.sym
rg -n "partial_name" .data\symbols\npc.sym .data\symbols\.local\npc.sym
rg -n "partial_name" .data\symbols\loc.sym .data\symbols\.local\loc.sym
rg -n "partial_name" .data\symbols\seq.sym .data\symbols\spotanim.sym .data\symbols\projanim.sym
```

Use MCP cache lookups for ambiguous candidates, then record the final `.sym` line in the manifest.

## Adding Refs

Prefer existing `Base*` refs. If a module needs a local wrapper, the wrapper must resolve to the
canonical sym name:

```kotlin
private object MyObjs : ObjReferences() {
    val raw_shrimp = find("raw_shrimp")
}
```

Only use compatibility aliases in Kotlin when needed to avoid a large call-site churn:

```kotlin
val chaosrune = find("chaosrune")
val chaos_rune get() = chaosrune
```

The alias is code-only. It is not a `.local/*.sym` alias.

## Legitimate `.local` Usage

Use `.data/symbols/.local/<type>.sym` only when the type is genuinely server-only or generated by
RSMod and has no base cache identity. Examples include server-only varps, content groups, or custom
interfaces created by this project.

Every `.local` addition must include in the task note:

- why the base cache has no symbol,
- how the ID was chosen,
- which validation commands passed.

## Validation Order

Run these before marking symbol-sensitive work complete:

```powershell
& 'C:\Program Files\PowerShell\7\pwsh.exe' -File "scripts\preflight-ref-hygiene.ps1" -FailOnIssues
& 'C:\Program Files\PowerShell\7\pwsh.exe' -Command ".\gradlew.bat validateSymbols --console=plain"
& 'C:\Program Files\PowerShell\7\pwsh.exe' -Command ".\gradlew.bat packCache --console=plain"
& 'C:\Program Files\PowerShell\7\pwsh.exe' -Command ".\gradlew.bat <scoped-module>:build --console=plain"
```

For cache builders, global config, startup scripts, symbol loaders, or generated type builders, also
run:

```powershell
& 'C:\Program Files\PowerShell\7\pwsh.exe' -File "scripts\strict-boot-probe.ps1" -TimeoutSeconds 120
```

Success means `packCache` passes and strict boot reaches `[MainGameProcess] World is live` with no
`Skipping script startup` lines.

## Failure Triage

| Failure | Meaning | Correct response |
| --- | --- | --- |
| `NameIdOverlap` | Two names claim the same ID in one loaded symbol file. | Remove the duplicate or use the canonical base symbol. |
| `internalId=-1` in cache edits | A builder/enricher generated a name that is not in `.sym`. | Fix the generator/config source; do not add aliases blindly. |
| `Duplicate key` during boot | Multiple functional refs share one dummy/cache ID. | Replace stubs with unique real symbols or disable the incomplete feature. |
| `Invalid hash` | Fallback ID or local mapping disagrees with cache identity. | Remove fallback/wrong mapping; resolve through canonical `.sym`. |
| Wiki ID mismatch | Wiki ID does not match rev 233 cache. | Use rev 233 `.sym`; record wiki only as behavior source. |

## Current Known P0 Pattern

If `packCache` reports missing spell object edit names such as `15_bones_to_bananas` or
`03_bake_pie`, treat it as a generator/ref mismatch. Do not solve it by adding `.local/obj.sym`
aliases until the generator path and rev 233 cache identity are proven.
